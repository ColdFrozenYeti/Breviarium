## Running it locally

`scripts/docker/docker-compose.yml` builds the container from this pinned checkout (not
the floating `ghcr.io/divinumofficium/divinum-officium:master` image mentioned in DO's own
README, which would drift out from under the pin):

```
docker compose -f scripts/docker/docker-compose.yml up --build -d
curl http://localhost:8080/cgi-bin/horas/officium.pl
docker compose -f scripts/docker/docker-compose.yml down
```

## Invocation, for M1/M4

DO's own regression tooling (`regress/scripts/generate-diff.sh`) does **not** go over
HTTP — it invokes the CGI script directly as a Perl program, with parameters passed as
`key=value` command-line arguments, e.g.:

```
perl web/cgi-bin/horas/officium.pl version="Rubrics 1960" command=prayVespera date=1-1-2025
```

`office_script_path`/`hour_command`/`long_version` in that same script show the exact
mapping from short version names (`1960` → `Rubrics 1960`) and hour names (`Vespera` →
`prayVespera`) DO itself uses. This is confirmed faster than the HTTP path for the
oracle-fixture sweep (no Starman/Plack request overhead per call) and is what
`scripts/generate-oracle-fixtures.sh`/`scripts/docker/oracle-worker.sh` actually use,
run inside the container so the Perl module environment from the Dockerfile (Plack,
CGI::Compile, etc.) is present.

Full parameter mapping, confirmed against the real container:

- `version="Rubrics 1960"`, `command=prayVespera`, `date=M-D-YYYY` (no leading zeros).
- `lang1=Latin` for the Vulgate psalter (the default since Beta 1; DO's own default,
  `horas.setup`'s `$psalmvar='0'`), `lang1=Latin-Bea` for the Pius XII psalter (the
  alpha's fixtures).
- For a Latin-only render, `lang2` equals `lang1` (`Latin` or `Latin-Bea`);
  `lang2=English` for parallel text. For Bea, **not**
  `lang2=Latin` with `psalmvar=1`: `officium.pl`'s own psalmvar-based `Latin`→`Latin-Bea`
  auto-upgrade only ever mutates *one* of `lang1`/`lang2` (each check reads the other's
  already-updated value in sequence), so it leaves them unequal and silently defeats the
  single-column collapse that requires `lang1 eq lang2` — confirmed by TD count and byte
  size in a real render before `oracle-worker.sh` was written to sidestep it entirely.
- `priest=1` for the priest form, omitted entirely for the "Domine, exaudi" form (Perl's
  `if ($priest)` treats both an unset param and the literal string `"0"` as false, but
  omitting is the closer match to the dialog's own Checkbutton semantics).
- `content=1` to get bare content, skipping the page chrome.

## Oracle fixtures

`data/oracle-fixtures/main/<year>.tar.gz` (2025-2040, Latin/Bea only, priest off — one
file per date) and `data/oracle-fixtures/spot-check.tar.gz` (~130 dates weighted toward
`CLAUDE.md`'s named edge cases, each rendered with the other three option combinations)
are generated by `scripts/generate-oracle-fixtures.sh`, which:

1. Builds the job manifest with `scripts/oracle-date-list.pl` (Easter via the standard
   anonymous Gregorian algorithm, used only to pick which real dates go into the spot
   check — not part of the engine itself).
2. Renders every job inside the container via `scripts/docker/oracle-worker.sh`,
   stripping the CGI header and HTML tags and collapsing whitespace.
3. Packs the result into the two `.tar.gz` sets above.

**J-to-I orthography is deliberately not applied at generation time** — the committed
fixtures still have DO's raw J-spellings. `Tests/OracleTests` applies
`BreviariumKit`'s own `LatinOrthography` at compare time instead, so fixture generation
has no Swift dependency and stays runnable from Docker alone (useful on a machine where
the local Swift toolchain isn't working).

### Hold-out years

`data/oracle-fixtures/holdout/<year>.tar.gz` holds every date of one year *outside* the
2025-2040 main sweep, rendered twice (priest off and priest on, Latin/Bea only), as an
out-of-sample check (`Tests/OracleTests/Holdout2044OracleTests.swift`). It is generated by
`scripts/generate-holdout-fixtures.sh <year>`, which uses the same
`scripts/docker/oracle-worker.sh`. It runs on the host against the pinned checkout
(`DO_ROOT`/`ORACLE_RAW` override the worker's container paths), which needs only Perl
with CGI.pm (Debian/Ubuntu: `libcgi-pm-perl`) for the CLI path. Host rendering was
verified byte-identical to the container-generated fixtures before use: all 365 dates
of 2026 (priest off) and all 128 priest-on/Latin spot-check files, 0 differences.

- **2044** (leap year, Easter 17 April): 732 renders, zero empty, 1.2 MB. Generated
  2026-09-24 against the pinned commit above; two runs were identical.

### Beta 1 sets: Vulgate and bilingual

Generated by `scripts/generate-fixture-set.sh <set> <first-year> <last-year>` on the host,
with the same `oracle-worker.sh`, which gained two optional fields: `lang1` (`Latin` is
the Vulgate, `Latin-Bea` the Pius XII psalter, the default so old manifests still work)
and the output format:
- **flat:** the whole page on one whitespace-collapsed line, as the alpha's sets;
- **rows:** one line per row of DO's table, the Latin and English cells separated by a
  tab and each normalised on its own; the first line is the text above the table (the
  day title). Bilingual sets use this so J-to-I can be applied to the Latin cell only
  and pairing can be checked row by row.

| Set | Path | Content | Size |
|---|---|---|---|
| Vulgate | `vulgate/<year>.tar.gz`, 2025-2040 | Vulgate Latin, priest off, flat, `<date>_priestN_latin.txt` | 9.7 MB |
| Bilingual | `bilingual/<year>.tar.gz`, 2025-2040 | Vulgate Latin + English, priest off, rows, `<date>_priestN_bilingual.tsv` | 23 MB |
| Hold-out | `holdout/2044-bilingual.tar.gz` | Vulgate Latin + English, priest off and on, rows | 1.6 MB |

Checks made on 2026-09-24, against the pinned commit above:
- **Host against container.** Host flat renders are byte-identical to the
  container-generated bilingual spot-check files (Bea + English), so the host renders
  English as the container does.
- **Rows against flat.** Joining a rows file's cells gives exactly the flat page.
- **Determinism.** The 2044 hold-out, generated twice, gave byte-identical archives
  (`tar --sort=name --mtime=@0`, `gzip -n`).
- **Integrity.** 5,844 renders per range set and 732 for the hold-out, none empty. Every
  table row has both cells, and no English cell is empty.
- **Latin column against the Latin-only page.** On all 5,844 dates, the bilingual Latin
  column equals the Vulgate Latin-only page. Tests can take Vulgate Latin from either
  set, and the 2044 Vulgate Latin test can read the bilingual hold-out.

### Beta 3 additions to the bundled data

- **`Tabulae/Stransfer/*.txt`**, the Scripture (initia) transfer tables that DO's
  `initiarule` reads, are bundled alongside `Tabulae/Transfer` in the same map, under an
  `S:` key prefix. Filtered to the 1960 tag, they hold one entry that matters for
  Matins: `01-12=Epi1-0a` in letter-`f` years.
- **Borrowed Monastic and Dominican files.** A few Roman offices reference files in
  `SanctiM/`, `CommuneM/`, `SanctiOP/`, `TemporaOP/` and the like (the Baptism of the
  Lord's `@SanctiM/01-06:AntMatutinumM:2`). `OfficeCorpusWalker.referencedSiblings`
  follows those references at build time and bundles just those files and what they
  reference in turn, in Latin and English. The rest of those folders stay out until the
  Dominican rite (Beta 5).
