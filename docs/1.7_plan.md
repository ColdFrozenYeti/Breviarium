# 1.7 plan: iPhone Duo, a tenth icon, Northumberland Inverted in Dark

## Context

The user asked for three things in 1.7 (17 November 2026):

1. **iPhone Duo support.** The Duo is Apple's foldable, released 23 October 2026. Its inner screen is 7.6" (1878×2670 px, probably about 669×951 pt, 4:3) and its outer screen is 5.4".
   - Apple's guidance (developer.apple.com/iphone-duo/prepare): an app built with the **iOS 26 SDK**, as ours is today (Xcode 26.5), runs on the Duo in a box in the middle of the screen with empty space around it. An app built with the iOS 27 SDK resizes to fill most of the screen. One built with the **iOS 27.1 SDK or later** is fully optimised: it runs edge to edge and its bars move below the status bar.
   - On the inner screen the app gets regular/regular size classes and isn't bound by its supported orientations.
2. **A tenth icon.** You'll send it later. It goes in the gallery as a choice, and the default stays Northumberland Simple.
3. **Dark Home Screen.** When the Home Screen is set to *Dark*, **Northumberland Simple and Northumberland** both show **Northumberland Inverted**. The other icons don't change.

Your other decisions:
- Unfolded and held sideways, the Duo shows a **two-page spread**, as the iPad does.
- **Every App Store screenshot is remade for 1.7 and sent to you**: iPhone, iPad, and a new iPhone Duo set.

The deployment target stays **iOS 26.0**. Only the SDK we build with changes, so every iPhone on iOS 26 can still install the app. No new capability or entitlement is needed, so the sideloaded build is unaffected.

## M2: Lay out properly on the iPhone Duo

The app is already SwiftUI plus the TextKit reader, and it lays out by available size, so little should change. These are the known spots:

- **Spread rule**, `App/Breviarium/Vespers/VespersView.swift:76` `isSpread`. Today it's horizontal pages, wider than tall, and `width >= 1000`, which rules out the Duo's roughly 951 pt.
  - The new rule: horizontal pages, wider than tall, `verticalSizeClass == .regular`, and `width >= 900`.
    - Regular height keeps out every iPhone held sideways, including the 956 pt Pro Max, since iPhones are compact height in landscape.
    - The Duo's inner screen and the iPad both report regular height.
  - Update the doc comment ("never an iPhone").
  - Side effect: an iPad window between 900 and 1000 pt wide in landscape also gets a spread. Check it in the iPad snapshot job.
  - `pageMargin` already widens the margins on regular-height pages, so a single upright page on the Duo gets iPad-like margins.
- **Facing-page English** follows `isSpread` automatically (`VespersView.swift:209-218`). The footer's page count does too (`:394-397`).
- **Folding and unfolding while reading:** the reader is rebuilt with `.id("\(readerID)|\(spread)")` and keeps its `readingAnchor`. Check that a fold or unfold keeps the place, as an iPad rotation already does. Apple says Duo apps resize dynamically.
- **The widget gallery** (debug only), `App/Breviarium/WidgetGalleryView.swift:99-101`, reads `UIScreen.main` and the device idiom, which Apple says not to do on the Duo.
  - Read the window scene's screen size instead.
  - Add the Duo's widget sizes from the HIG's *Widgets › Specifications* if Apple has published them. Otherwise flag them as interpolated, as the 402 pt iPhones are now.
- Search the whole app (`App/`, `App/BreviariumWidget/`, `App/Shared/`) for `UIScreen.main`, `UIDevice.current`, orientation checks, `userInterfaceIdiom` and `horizontalSizeClass == .regular` used to mean "iPad", and fix each one. The first search found only the widget gallery.
- **Widgets** (`App/BreviariumWidget/`) are already sized by the system's families. Check them in the Duo simulator gallery.
